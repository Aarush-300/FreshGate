# FreshGate Strategic Implementation Plan

## Context
FreshGate is a web-based AI gateway middleware with React dashboard that verifies time-sensitive factual claims in AI responses. The system needs strategic enhancements to meet GeekRoom AI Hackathon requirements, focusing on differentiation through advanced verification capabilities, predictive monitoring, and improved user experience.

## Codebase Analysis Summary (from exploration)

**Key Architectural Patterns Found:**
- **Modular Pipeline**: Extraction → Triage → Verification → Scoring → Persistence → Monitoring
- **Immutable Snapshots**: Verification results are append-only with database triggers enforcing immutability
- **Lease-based Concurrency**: Watchtower uses atomic lease system to prevent duplicate processing
- **Fail-Open Design**: Default `fail_open: true` for production availability
- **Request-Scoped Credentials**: Provider keys used once per request, never persisted
- **Configuration-Driven**: Environment-based config with validation in `core/config.py`
- **Single-Page React App**: Hash-based routing, 7 views, centralized polling, no external state library

**Existing Capabilities to Leverage (Critical - Do Not Rebuild):**
- `scorer.py`: Discrete linear decay (1.0 at 30 days → 0.5 at 365 days) — **enhance with multiple decay curves**
- `SourceValidator` (`sources.py`): Sophisticated multi-source evidence triangulation with domain authority tiers — **extend with new source types**
- `WatchtowerService` (`watchtower.py`): Complete scheduling, retry, lease, and alert infrastructure — **add prediction methods**
- `history.py` + `persistence.py`: Immutable snapshot storage with replay/compare APIs — **build export on this foundation**

1. **Add prediction methods to `WatchtowerService`** (`watchtower.py`):
   ```python
   def predict_optimal_check_interval(self, claim: Claim) -> int:
       # Based on volatility_score + evidence freshness + half-life
       if claim.volatility_score > 0.7:
           return min(claim.freshness_half_life_seconds or 86400, 3600)
       return claim.freshness_half_life_seconds or 86400
   
   def calculate_flip_probability(self, claim: Claim) -> float:
       # volatility_score * (1 - evidence_confidence) * recency_factor
   ```

2. **Enhance `_scheduler_loop()`** (`watchtower.py`):
   - Add priority queue: sort due claims by `flip_probability` descending
   - Check high-probability claims first within concurrency limit

3. **Enhance scoring with predictive indicators** (`scorer.py`):
   - Add `predicted_flip_probability` and `recommended_interval` to `compute_score_dimensions()` output
   - Store these in `Claim` and persist via `save_claim_snapshot()`

4. **Update `MonitorRequest`** (`server/routes/watchtower.py`):
